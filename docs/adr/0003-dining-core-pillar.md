# Dining is a core pillar, not a gated amenity

The plan treated the Restaurant as a buildable amenity gating 2★, with a Chef role only affecting a "meal quality" modifier. The prototype instead built a full live-service loop — breakfast each morning, walk-in dinner each evening, a Kitchen Station, arrival/Patience queues, and a Daily Special — running the Terrace as a fixed structure present from day one, never built or unlocked.

We're keeping the Terrace fixed from day one (like Reception, not like a Room), with Dining promoted to a core pillar on par with check-in and Housekeeping. Two changes to the prototype's current code follow from this: the Terrace should receive purchasable/earnable upgrades the same way Rooms do, and Dining outcomes (Walk-in Diners and room guests' dinner add-on) should feed Reputation and Hearts, not stay a cash-only side loop as currently implemented. Other amenities (Pool, Sauna, Perch Garden) are unaffected — they remain separate buildable slot-occupants.

Status: accepted, supersedes the amenity framing of Restaurant in `hotel_habitat_plan.md` §3.6 and the cash-only dining implementation in `habitat-hotel-prototype-4.html`.
