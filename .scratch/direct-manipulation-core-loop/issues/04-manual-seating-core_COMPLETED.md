# 04 — Manual seating core

**What to build:** Replace the auto-matcher entirely (ADR-0001). Arriving Parties become a queryable pending queue instead of resolving invisibly within one phase; each entry carries a decaying Patience value. A pure match-hint function classifies a candidate Room against a selected Party's Species/Needs as green (every Need met), amber (seatable, missing a Need), or none (too small, occupied, dirty, or unaffordable for the Party's budget tier). A single seat action performs the actual admission (Satisfaction, cash/Hearts/Reputation bookkeeping, lifecycle signals) and is the only path to seating a Party — interactive play and any scripted autopilot both call it. A Party larger than one Room's capacity can be split across Rooms, with the unseated remainder staying in the queue with its Patience preserved. A Party whose Patience runs out walks away using the existing three reasons (no eligible Room type, fully booked, too expensive), computed the same way the auto-matcher used to compute them. The auto-matcher's policy branching and the global seating-policy setting are deleted.

**Blocked by:** 02

**Status:** done

- [x] Arrivals are queryable as a pending queue with per-entry Patience that decays over the day rather than being resolved instantly
- [x] The match-hint function returns green/amber/none correctly across Need-coverage, capacity, dirty/occupied, and affordability cases
- [x] The seat action is the only code path that admits a Party into a Room, for both green and amber matches (amber applies the existing mismatch handling)
- [x] An oversized Party can be split across multiple Rooms in one or more seat actions, with the remainder still queued and its Patience unchanged by the partial seating
- [x] A Party whose Patience expires walks away with the correct reason and the same reputation/economy effects the old auto-matcher produced for that reason
- [x] The auto-matcher's policy branching and the global policy setting no longer exist anywhere in the sim

## Comments

`sim/matcher.gd` is deleted and replaced by `sim/match_hint.gd` (`MatchHint`, a pure `RefCounted` module like `Satisfaction`/`DemandGenerator`): `MatchHint.classify(party, room, room_stats, price_multipliers, pricing_balance)` returns green/amber/none for a single candidate Room (capacity<1/occupied/dirty/unaffordable -> none; deliberately does NOT compare capacity against the Party's *full* size, since an undersized Room is a valid split target, not a rejection), and `MatchHint.walk_away_reason(...)` reproduces the old auto-matcher's three reasons for an expired Party, with one documented new branch: an affordable, fully-matching Room that sat vacant the whole time (impossible under the old always-seat-immediately auto-matcher) is folded into `"no_match_available"` since it's still a real missed service from the guest's point of view -- flagged for the balance owner's awareness, not a literal port of old logic.

`autoload/sim_controller.gd` (`Sim`) gained a public `pending_arrivals: Array` of Party dicts (`id`, `name`, `species_id`, `needs`, `likes`, `amenity_prefs`, `budget`, `party_size`, `nights_total`, `patience`) -- this queue *is* Reception's future UI model, not an internal detail. `Sim.match_hint(party_id, room_type_id, instance_id)` and `Sim.seat_party(party_id, room_type_id, instance_id)` are the new public API; `seat_party` is the sole admission path (both green and amber), seats `min(room_capacity, party.party_size)`, and leaves any remainder queued with its Patience field untouched. Patience decays by `data/balance.json`'s new `patience.decay_per_tick` once per tick while `Clock`'s current phase is MIDDAY (tracked via a new `_midday_active` flag set from `phase_changed`); an Evening-phase sweep force-expires anything still queued as a defensive safety net (Patience's configured `start` is comfortably under Midday's tick count, so in practice this never fires). `autoload/clock.gd` gained `force_advance_ticks(n)` (the primitive `force_advance_day()` is now built on) so tests can land mid-Midday.

`GameState.matcher_policy`/`DEFAULT_MATCHER_POLICY` are gone; `reset_to_starting_conditions()` no longer takes a policy argument. `ui/policy_menu.gd` is deleted and the Policy entry removed from `ui/main_screen.gd`'s menu bar. `sim/batch_runner.gd` no longer takes a `policy` argument; until ticket 06 wires up scripted autopilot seating, a batch run simply characterizes every arrival walking away on expired Patience (no second admission path exists to seat them).

New tests: `tests/test_match_hint.gd` (pure classify()/walk_away_reason() cases, mirroring the deleted `test_matcher_policies.gd`'s style) and `tests/test_manual_seating.gd` (queue/Patience-decay/seat/split behavior against the real `Sim`/`Clock` autoloads, using `Clock.force_advance_ticks()` to land mid-Midday). `tests/test_day_night_cycle.gd` and `tests/test_checkout_review.gd` were rewritten: nothing auto-seats any more, so a bare `Clock.force_advance_day()` now characterizes every Day-1 arrival walking away by Evening; the checkout/review path is re-exercised through a hand-built Party admitted via `Sim.seat_party()` instead of relying on `DemandGenerator`'s RNG output, and a shared `make_party()` helper landed on `tests/helpers/sim_test_base.gd` to avoid duplicating that Party-dict literal across files.
