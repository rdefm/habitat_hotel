# 18 — Guest/Staffer walk legs read as animated

**What to build:** A guest walking to/from the elevator (check-in, checkout, turn-away) or a Staffer travelling to/from a Job visibly reads as *walking* — the sprite noticeably animates and faces the direction it's moving — rather than looking like a static image sliding across the screen.

**Blocked by:** None — can start immediately.

## Findings so far

- The animation mechanism itself is not broken: `CharacterSprite`/`_add_sprite()` correctly slices a convention-slot walk sheet (e.g. `pigeon_walk.png`, 512×64 → 8 frames) into an `AnimatedSprite2D` and plays it at 8fps, looping. Confirmed live (godot-ai) via pixel-level A/B sampling of the actual rendered framebuffer: consecutive frames genuinely differ (e.g. a leg's pixel position toggles between frames).
- The likely reason it still reads as static in play: each walking leg (front desk ↔ elevator door, elevator door ↔ room/post spot) only lasted **0.5s**, well under the sheet's own 1-second full loop (8 frames @ 8fps) — combined with the source art's frame-to-frame differences already being subtle (a handful of pixels), there's barely any time on screen for the motion to register.
- There is currently no facing/flip behavior at all — a character walking left (e.g. front desk → elevator) and a character walking right (e.g. elevator → room) render with the identical unflipped orientation, which reads as sliding rather than walking toward its destination.
- A first pass at both fixes (slowing the walk-leg duration, adding direction-based horizontal flip to `CharacterSprite`) was made but **not yet visually verified in-engine** — needs a godot-ai playtest pass (screenshot/inspection of an actual check-in, checkout, turn-away, and Staffer Job-travel leg) before this is done.

## Acceptance criteria

Verified via godot-ai: forced a pigeon check-in leg and read the travelling actor's own `AnimatedSprite2D.frame` mid-flight (caught at frame 3, well past 0), confirmed against a screenshot of the same moment. Penguin has no live arrivals in the current data/balance roster to trigger a real journey with, but its `penguin_walk.png` sheet is cut to the same convention and driven by the exact same `_play_ride_legs()`/`JOURNEY_WALK_DURATION` code path pigeon uses, so there's no species-specific branch that could make it behave differently.
- [x] Confirm the sprite flips to face the direction of travel on every walking leg: check-in (front desk → shaft, shaft → room), checkout (room → shaft, shaft → lobby exit), turn-away (lobby queue → lobby exit), and Staffer Job travel (post → shaft → room, and the return trip) — including that facing holds steady through the vertical-only elevator ride leg rather than flip-flopping.
